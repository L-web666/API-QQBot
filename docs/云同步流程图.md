## 一、全流程总览

```mermaid
flowchart TD
    START(["程序启动"]) --> CFG["读取 config.json / 建立日志"]
    CFG --> QQ{"qq.app_id / app_secret 已填？"}
    QQ -- 否 --> STOPX["ERROR：拒绝启动"]
    QQ -- 是 --> AI["校验 AI 配置（可选）"]
    AI --> CSINIT["_init_cloud_sync()<br/>建 D1Backend（★ 启动阶段不访问网络）"]

    CSINIT --> CSON{"cloud_sync.enabled<br/>且凭据完整？"}
    CSON -- 否 --> SKIP["跳过云同步<br/>（不缓存、也不提示，行为与没有这个功能一致）"]
    CSON -- 是 --> BUF["★ 启动写缓存开启<br/>data/ 下的数据改动先记在内存里<br/>（日志 / config.json 例外，立即落盘）"]
    BUF --> WAITMSG["WARNING：刚启动这段时间<br/>本地数据可能不是最新的"]
    WAITMSG --> MODS["_init_modules()<br/>上下文 / 统计 / 插件加载<br/>★ 插件的启动写入被缓存，还没落盘"]
    SKIP --> MODS
    MODS --> RUN["run()：消息处理 / 热更新 / 定时任务 / Web 后台 / 连接 QQ"]

    RUN --> AFTER["连接 QQ 成功<br/>cloud_sync.start(immediate=True)"]
    AFTER --> FIRST["第一次同步：完整跑一轮 A→B→C→D→E<br/>（同步期间临时挂起写缓存，必须看到磁盘真实状态）"]
    FIRST --> NOTICE["控制台 INFO：<br/>✅ 第一次同步已完成：恢复 N / 上传 M / 删除 K，用时 T 秒"]
    NOTICE --> FLUSH["写回启动缓存<br/>刚被云端恢复过的文件默认放弃本地改动<br/>（startup_buffer_keep_remote=false 则本地优先）"]
    FLUSH --> THREAD

    THREAD["cloud-sync daemon 线程<br/>每 interval_seconds 一轮"] --> LOOP{{"循环：每 interval_seconds 写入一次<br/>默认 60 秒；≥60 秒对齐整点倍数"}}
    LOOP --> S0["A 应用云端删除标记<br/>墓碑比本地新 → 删本地副本（防复活）"]
    S0 --> S1["B 本地删除 → 写墓碑<br/>deleted=1 + 删除时间"]
    S1 --> S2["C 上传<br/>有改动的文件 → 批量 INSERT（30 行/批）"]
    S2 --> S3["D 下载<br/>本地缺失 / 云端较新 → 写回本地并同步 mtime"]
    S3 --> S4["E 清理过期墓碑 + 实例心跳<br/>保存 .cloud_sync_state.json"]
    S4 --> WAIT["等到下一个时间点<br/>（无改动的周期完全不写库）"]
    WAIT --> LOOP

    LOOP -.-> ERR["失败：记 WARNING，下个周期重试<br/>同一文件连续 3 次 → ERROR + 暂停"]
    RUN -.-> BTN["状态页按钮：🔌 测试连接 / ⬆️ 立即同步一次 / ⏸ 解除暂停"]
    RUN -.-> HOT["配置热更新：cloud_sync 有变化<br/>→ 停旧线程（末次同步）→ 重建 → 重启线程"]

    RUN --> STOP(["退出 / stop()"])
    STOP --> STOP1["停止热更新、定时任务线程"]
    STOP1 --> STOP2["停止 Web 管理后台"]
    STOP2 --> STOP3["cloud_sync.stop(final_sync=True)<br/>停线程 + 再做一次完整同步"]
    STOP3 --> STOP4["启动缓存兜底写回磁盘<br/>（首次同步一直没成功时）"]
    STOP4 --> STOP5["停消息处理器 → 断开 QQ → 程序已停止"]
    STOP -.-> CRASH["崩溃 / kill -9 不会执行退出同步<br/>最大丢失窗口 = interval_seconds"]
```

## 一·补、启动写缓存（startup write buffer）

```mermaid
flowchart TD
    A(["程序启动（已启用云同步 + 凭据完整）"]) --> B["拦截 data/ 下数据文件的写入/删除/改名<br/>（内置 open / os.remove / os.rename / os.path.* 包装）"]
    B --> C{"文件会被同步吗？"}
    C -- "否（logs/、config.json、.cloud_sync_state.json、bot.lock、*.tmp…）" --> D["直接写磁盘（日志永远立即落盘）"]
    C -- "是" --> E["内容记在内存里<br/>读取 / exists / getsize 都按缓存回答"]
    E --> F{"第一次云同步结果？"}
    F -- "成功完成" --> G["按顺序写回磁盘"]
    F -- "超时 / 云同步暂停 / 程序退出" --> H["WARNING + 立即写回磁盘（不丢数据）"]
    G --> I{"该文件刚被同步从云端恢复过？"}
    I -- "是（默认）" --> J["放弃这份本地改动，WARNING 列出文件名<br/>→ 云端数据不会被启动时的旧数据覆盖"]
    I -- "否" --> K["本地改动生效，下个周期上传到云端"]
    H --> K
```

要点：

- **只影响会被同步的数据文件**；日志、`config.json` 等不受影响（永远直接写盘）。
- **没启用云同步（或凭据不完整）时整个机制不生效**：不缓存、不延迟、也没有任何云同步相关提示。
- 同步自己读写的文件（云端下载、`.cloud_sync_state.json`）会**临时挂起**缓存，必须看到磁盘真实状态。
- 等待上限 `cloud_sync.startup_buffer_minutes`（默认 3 分钟），超时就先落盘，避免数据一直不写；
  填 0（不限时间）时也有 30 分钟兜底。
- 容量上限 `cloud_sync.startup_buffer_max_mb`（默认 8MB）：超过就立刻落盘并停止缓存（之后的写入直接写磁盘），
  即使填 0 也有 128MB 硬上限 —— 保证缓存占用的内存永远有界。


## 二、sync_once() 的五个阶段（顺序很重要）

```mermaid
flowchart LR
    L["读取云端记录<br/>SELECT key, updated_at, deleted（分页 500）"] --> A
    A["A 应用云端删除标记<br/>墓碑比本地文件新 → 删除本地副本<br/>本地更新 → 标记待复活"] --> B
    B["B 本地删除 → 写删除标记<br/>本地“同步过但现在没有”的文件<br/>→ upsert 墓碑（deleted=1 + 删除时间）"] --> C
    C["C 上传改动<br/>毫秒级 mtime + 大小 比对<br/>★ 云端副本更新 → 本轮不上传（改用云端版本）<br/>→ 批量 INSERT（deleted=0，可覆盖旧墓碑）"] --> D
    D["D 下载<br/>只下载 deleted=0 的记录<br/>本地缺失 或 云端更新 → 写回本地"] --> E
    E["E 清理过期墓碑<br/>默认保留 30 天（daily）"] --> F["保存 data/.cloud_sync_state.json"]
```

> C 阶段的"云端更新就不上传"很关键：新机器 / 同步状态文件丢失时，本地可能放着很旧的副本，
> 旧逻辑会先把它传上云，于是**云端的较新数据被本地旧数据覆盖**。现在按时间戳判断谁更新，
> 并把决定写进控制台 WARNING（`有 N 个文件的云端版本比本地新…`），下个周期本地已是最新，不会重复提示。

## 二·补、删除墓碑（tombstone）机制

```mermaid
flowchart TD
    DEL["用户删除（如 /clear 清空上下文）"] --> T["云端写入删除标记<br/>key + deleted=1 + 删除时间（毫秒）"]
    T --> Q1{"其它机器/新服务器的本地副本<br/>比标记旧还是新？"}
    Q1 -- 本地更旧 --> K1["删除本地副本<br/>（applied_remote_deletes=true 时）"]
    Q1 -- 本地更新 --> K2["保留本地并重新上传<br/>→ 覆盖墓碑（last-write-wins）"]
    Q1 -- 本地根本没有 --> K3["什么都不做<br/>绝不会把已删数据下载回来"]
    T --> GC["超过 tombstone_days 天<br/>自动清理标记"]
    K1 --> WIN["结果：删除被正确传播，数据不会“复活”"]
    K2 --> WIN
    K3 --> WIN
```


## 三、同步范围与规则

```mermaid
flowchart TB
    subgraph UP["会上云"]
        U1["user_context/** 私聊/群聊上下文 + bindings.json"]
        U2["stats.json 统计"]
        U3["plugins_data/** 插件数据"]
        U4["plugins_disabled.json / command_panel.json"]
    end
    subgraph NEVER["永不上云"]
        N1["config.json / config配置说明文件.txt（含密钥）"]
        N2["bot.lock / bot.pid（运行期文件）"]
        N3[".cloud_sync_state.json / _test* / *.tmp"]
        N4["data/logs/**（默认不上云，upload_logs=true 才开）"]
    end
    subgraph RULE["冲突规则"]
        R1["同一记录以时间戳更新的一方为准：云端更新 → 覆盖本地；本地更新 → 覆盖云端"]
        R2["本地删除 → 写删除标记（墓碑），不被复活"]
        R3["云端删除标记更新 → 删除本地副本（可关闭）"]
        R4["本地数据绝不因“云端没有”而被删除"]
        R5["同一时间只跑一台机器人（按 key 覆盖）"]
        R6["启动期间改动：先缓存 → 首次同步完成后再落盘（默认：刚被云端恢复的文件放弃本地改动）"]
    end
    subgraph LIMIT["限制"]
        L1["单文件 > max_file_mb（默认 2MB）→ 跳过"]
        L2["非 UTF-8 文本 → 跳过"]
        L3["间隔下限 10 秒，建议 60~300 秒"]
        L4["墓碑默认保留 30 天（tombstone_days）"]
        L5["启动缓存最长等 startup_buffer_minutes（默认 3 分钟），超时先落盘"]
    end
```

## 四、数据表

```sql
CREATE TABLE IF NOT EXISTS bot_data (
  key        TEXT PRIMARY KEY,   -- 如 data/user_context/private/<openid>.json
  value      TEXT NOT NULL,      -- 文件全文（删除标记时为空）
  updated_at INTEGER NOT NULL,   -- 文件修改时间 / 删除时间（毫秒）
  deleted    INTEGER NOT NULL DEFAULT 0   -- 0=正常文件  1=删除标记（墓碑）
);
```
首次连接由程序自动创建；老版本的表会自动 `ALTER TABLE` 补上 `deleted` 列（「🔌 测试连接」也会做这件事）。
